# SiteArchitect 11 · Оновлення v2 (учні без email + оцінки)

## Що нового

- Учень натискає «Я учень», вводить **ім'я та прізвище, клас** і починає роботу **без email, пароля та підтвердження пошти**.
- Supabase створює кожному учневі **тимчасовий анонімний Auth-сеанс**. Це не є публічним або спільним обліковим записом — кожен отримує свій UUID.
- Учень бачить лише власні роботи; вчитель бачить всі, використовуючи свій існуючий обліковий запис.
- Учитель може виставити **1–12 балів** та записати коментар; учень побачить їх у своїй роботі.
- Вчитель може фільтрувати роботи, експортувати CSV з оцінками й коментарями, завантажувати схеми PNG/JSON.
- SQL-оновлення **не видаляє попередні проєкти, профілі, ролі та налаштування**.
- Від одного анонімного учнівського сеансу пропонується **один проєкт**, щоб домашнє завдання не перетворювалося на випадковий набір чернеток. Уже створені кілька робіт залишаються доступними.

## Як оновити ваш уже працюючий сайт

### 1. Supabase — виконайте SQL-міграцію

Відкрийте **Supabase → SQL Editor → New query**. Скопіюйте **повний** вміст файлу **`migration_v2.sql`** і натисніть **Run**. Запит створить лише нову таблицю оцінок та захисні політики. **Повторно запускати старий `schema.sql` не потрібно.**

Очікуване повідомлення: `Success. No rows returned`.

### 2. Увімкніть анонімні входи

Supabase → **Authentication → Sign In / Providers** → знайдіть **Anonymous Sign-Ins** → увімкніть (Enable). Назва пункту може дещо змінюватися з оновленнями панелі.

Цей перемикач **не** означає, що БД стає загальнодоступною. Анонімний Auth-користувач має окремий ID, JWT і доступ через RLS. Політики таблиць `profiles`, `site_projects` і `site_project_reviews` залишаються захищеними.

Для відкритого публічного сайту бажано додатково налаштувати **CAPTCHA** (Supabase підтримує Cloudflare Turnstile / hCaptcha), щоб обмежити автоматичне створення тимчасових акаунтів. Ця версія не містить вбудованої інтеграції CAPTCHA, тому за її обов'язкового ввімкнення в Supabase студентський вхід потребуватиме окремого доопрацювання.

**Не вимикайте email-підтвердження для наявного вчительського акаунту**. SMTP для анонімного входу учнів не потрібний.

### 3. GitHub — замініть два файли

Відкрийте https://github.com/prostovchytel-debug/SiteArchitect і замініть **тільки `app.js` та `styles.css`** на їхні нові версії з цього архіву. GitHub: **Add file → Upload files → Commit changes** (або відредагуйте відповідні файли).

**ВАЖЛИВО: залиште без змін ваш теперішній `config.js`** — він уже містить Project URL і публічний ключ Supabase. У цьому архіві є тільки `config.example.js` з порожніми полями, **не** завантажуйте його замість робочого `config.js`.

Файли `index.html`, `boot.js`, `favicon.svg` від попередньої версії не потрібно змінювати. Після коміту натисніть `Ctrl + Shift + R` на https://prostovchytel-debug.github.io/SiteArchitect/ .

### 4. Перевірка — ОБОВ'ЯЗКОВО до роздачі завдання класу

1. Відкрийте **окреме інкогніто-вікно** та перейдіть на сайт. На вкладці «Я учень» введіть тестові ім'я та клас; натисніть «Розпочати проєкт».
2. Створіть тестовий проєкт, заповніть паспорт, додайте 5 сторінок (з описами й 2 блоками), перевірте глибину та назви. Натисніть «Здати роботу». Переконайтеся, що є повідомлення про здачу.
3. В іншому браузері зі **звичайним обліковим записом учителя** відкрийте «Кабінет учителя → Оновити роботи». Тестова робота має з'явитися у списку «Лише здані».
4. Відкрийте роботу, виставте оцінку та напишіть коментар, натисніть «Зберегти оцінку та коментар».
5. В учнівському інкогніто-вікні оновіть сторінку (не виходьте із сеансу), перевірте відображення відгуку.
6. Спробуйте в **іншому** інкогніто-вікні створити другого тестового учня — чужі роботи не повинні бути доступними.
7. Перевірте експорт PNG і CSV. **Вилучати відомості про тестових учнів треба з Supabase обережно**: видалення Auth-користувача призведе до каскадного видалення його робіт.

## Важлива відмінність від звичайної реєстрації

Анонімний учень **не може повторно увійти** після виходу, очищення сховища браузера або переходу на інший пристрій. Якщо учень просто закриє вкладку, але збереже той самий браузер із локальним сховищем, Supabase зазвичай відновить сеанс автоматично.

Увага: на **спільному шкільному ПК** інший учень може побачити попередній сеанс, якщо перший не вийшов. Тому домашнє завдання краще виконувати **на особистому пристрої**. За потреби після здачі учень має завершити сеанс, розуміючи, що його вже не відновити.

ПІБ у тимчасовому вході — це **введені користувачем дані, а не підтверджена особа**. Не використовуйте цей механізм для офіційного засвідчення особи чи високоризикового оцінювання. Доступ до робіт учнів обмежується RLS. Учитель може співвіднести ПІБ і клас з учнівським списком.

## Важливе про базу

Новий файл `migration_v2.sql` додає таблицю `site_project_reviews` із полями `project_id`, `grade`, `comment`, `reviewed_by`, `reviewed_at`. Студент отримує лише SELECT для відгуків **своєї** роботи, вчитель — INSERT/UPDATE/SELECT, причому лише на вже здані проєкти. Статус і сам JSON проєкту не змінюються цією міграцією.

Здані роботи тепер не можна видалити учнівською кнопкою. У разі редагування після оцінювання вчитель та учень побачать позначку, що робота змінена після перевірки. Це не є автоматичною повторною оцінкою.

### Вимоги до безпеки

- Ніколи не вставляйте `service_role`/`secret key` у `config.js`.
- Не робіть таблиці `profiles`, `site_projects`, `site_project_reviews` загальнодоступними.
- Для мінімізації даних не просіть дітей вводити телефони, домашні адреси або інші додаткові персональні відомості.
- Регулярно перевіряйте кількість анонімних користувачів, обмеження тарифу Supabase, політики зберігання даних.
- Якщо потрібні жорсткіші гарантії проти чужих або масових надсилань, додайте класний PIN або CAPTCHA / запрошення з обмеженим терміном дії.
